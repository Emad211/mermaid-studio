# راهنمای داشبورد بازدید، درآمد و SEO

Mermaid Studio یک سامانهٔ تحلیل first-party دارد که بدون Google Analytics یا سرویس خارجی کار می‌کند. هدف آن اندازه‌گیری رشد محصول و درآمد تبلیغات بدون ذخیرهٔ کد Mermaid، متن نمودار یا IP خام است.

## فعال‌سازی production

در `.env` این مقادیر را تنظیم کنید:

```dotenv
ANALYTICS_ENABLED=true
ANALYTICS_RESPECT_DNT=true
ANALYTICS_DATA_DIR=/data/analytics
ANALYTICS_TIME_ZONE=Asia/Tehran
ANALYTICS_RETENTION_DAYS=400
ANALYTICS_ESTIMATED_RPM_RIAL=0
ANALYTICS_ADMIN_USER=admin
ANALYTICS_ADMIN_PASSWORD=...
ANALYTICS_HASH_SECRET=...
```

رمز و secret را مستقل و تصادفی تولید کنید:

```bash
openssl rand -base64 32
openssl rand -hex 32
```

ترکیب رسمی Docker Compose تا زمانی که این دو مقدار خالی باشند اجرا نمی‌شود. داده‌ها در volume مستقل `analytics_data` نگهداری می‌شوند.

## ورود به داشبورد

پس از انتشار، مسیر زیر را باز کنید:

```text
https://YOUR_DOMAIN/admin/analytics
```

مرورگر پنجرهٔ HTTP Basic Auth نمایش می‌دهد. داشبورد با هدر `noindex` محافظت شده و در sitemap قرار نمی‌گیرد. دسترسی باید فقط روی HTTPS انجام شود.

## شاخص‌های ترافیک و محصول

داشبورد این داده‌ها را ثبت و تجمیع می‌کند:

- بازدید صفحه
- جلسهٔ یکتا و کاربر یکتای روزانه
- مدت تعامل و نرخ پرش تقریبی
- نرخ ورود از صفحات محتوا به ادیتور
- رندر موفق و ناموفق
- تعداد و فرمت خروجی‌ها
- اشتراک‌گذاری و کپی SVG
- صفحه‌های پربازدید
- referrer، کانال ورودی و UTM کمپین
- نوع دستگاه، مرورگر و سیستم‌عامل
- نمایش بالقوهٔ جایگاه، موفقیت لود اسکریپت و خطای ad blocker

«کاربر یکتا» در این سامانه معادل کاربر یکتای روزانه است. برای جلوگیری از ساخت پروفایل دائمی، hash هر روز تغییر می‌کند و کاربر میان روزهای مختلف دنبال نمی‌شود.

## Core Web Vitals

دادهٔ واقعی کاربران برای این معیارها ثبت می‌شود:

| معیار | هدف خوب |
|---|---:|
| LCP | حداکثر ۲.۵ ثانیه |
| INP | حداکثر ۲۰۰ میلی‌ثانیه |
| CLS | حداکثر ۰.۱ |
| TTFB | هدف داخلی ۸۰۰ میلی‌ثانیه |
| FCP | هدف داخلی ۱.۸ ثانیه |

داشبورد صدک ۷۵ را نمایش می‌دهد. برای تصمیم‌گیری، دادهٔ چند هفته و تفکیک موبایل/دسکتاپ را در نظر بگیرید؛ یک میانگین کوتاه‌مدت برای قضاوت SEO کافی نیست.

## ثبت درآمد واقعی تبلیغات

شناسه و درآمد هر ناشر داخل پنل همان حساب است. سامانه به API خصوصی یکتانت یا تپسل دسترسی ندارد؛ بنابراین عدد معتبر باید از گزارش پنل وارد شود.

در بخش «ثبت درآمد واقعی» این داده‌ها را وارد کنید:

- تاریخ
- شبکه: یکتانت، تپسل یا سایر
- نام جایگاه
- impression
- click
- درآمد به ریال
- یادداشت اختیاری

از این اطلاعات شاخص‌های زیر محاسبه می‌شوند:

```text
Page RPM = revenue / pageviews × 1000
eCPM = revenue / ad impressions × 1000
CTR = clicks / impressions × 100
CPC = revenue / clicks
Fill-rate approximation = impressions / visible ad slots × 100
```

Fill rate فقط یک برآورد است؛ چون «قرار گرفتن جایگاه در دید کاربر» با ad impression معتبر پنل شبکه یکسان نیست.

اگر هنوز درآمد واقعی ندارید، `ANALYTICS_ESTIMATED_RPM_RIAL` را فقط برای سناریوسازی وارد کنید. رقم برآوردی در داشبورد از درآمد واقعی جدا نمایش داده می‌شود.

## دادهٔ Search Console

از بخش Performance سرچ کنسول یک CSV شامل query یا page، clicks، impressions و position بگیرید. محتوای CSV را در فرم «ورود CSV سرچ کنسول» Paste کنید.

داشبورد این موارد را محاسبه می‌کند:

- کلیک ارگانیک
- نمایش در نتایج
- CTR جست‌وجو
- جایگاه متوسط وزنی
- عبارت‌های پربازده
- صفحه‌های دارای impression زیاد و CTR پایین

برای جلوگیری از دوباره‌شماری، هر خروجی را با بازهٔ زمانی مشخص وارد کنید. اگر لازم است دادهٔ یک روز اصلاح شود، رکوردهای مربوط به آن بازه را در فایل ذخیره‌سازی مدیریت یا دادهٔ جدید را با برنامهٔ نگهداری سرور جایگزین کنید.

## حریم خصوصی

- کد Mermaid و متن نمودار هرگز event تحلیلی نیست.
- IP خام روی دیسک نوشته نمی‌شود.
- برای visitor/session از HMAC روزانه استفاده می‌شود.
- پارامتر کامل query ذخیره نمی‌شود؛ فقط `utm_source`، `utm_medium` و `utm_campaign` ثبت می‌شوند.
- Do Not Track و Global Privacy Control به‌طور پیش‌فرض رعایت می‌شوند.
- داده‌ها به‌صورت فایل‌های JSON روزانه و atomic ذخیره می‌شوند.
- retention پیش‌فرض ۴۰۰ روز است و می‌تواند کمتر شود.

## پشتیبان‌گیری

برای backup volume:

```bash
docker run --rm \
  -v mermaid-studio_analytics_data:/source:ro \
  -v "$PWD/backups:/backup" \
  alpine sh -c 'tar czf /backup/analytics-$(date +%F).tar.gz -C /source .'
```

فایل backup شامل آمار تجمیعی و درآمد واردشده است؛ آن را مانند دادهٔ مدیریتی محرمانه نگهداری کنید.

## کنترل سلامت

```bash
curl -fsS https://YOUR_DOMAIN/api/health
```

بخش analytics وضعیت فعال‌بودن، تنظیم رمز مدیریتی، ثابت‌بودن secret و آخرین خطای ذخیره‌سازی را گزارش می‌کند. `persistentHashSecret` در production باید `true` باشد.
