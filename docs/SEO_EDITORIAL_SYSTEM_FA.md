# سیستم روزانهٔ مقاله‌نویسی و SEO نمودارا

این سند روش رسمی تولید، انتشار، ارزیابی و به‌روزرسانی محتوای `nemodara.ir` است. هدف، افزایش تعداد صفحه‌ها به هر قیمت نیست؛ هدف ساختن مرجع فارسی قابل اعتماد برای Mermaid، نمودار به‌صورت کد و مستندسازی فنی است.

## خروجی روزانه

هر بستهٔ روزانه باید یک خوشهٔ واحد را پوشش دهد:

1. **یک مقالهٔ تحلیلی** در `/articles/...` برای پاسخ به سؤال تصمیم‌محور، مقایسه‌ای یا مسئلهٔ واقعی تیم‌ها.
2. **یک آموزش عملی** در `/learn/...` با مثال‌های قابل رندر، مراحل روشن و FAQ.
3. **یک قالب Mermaid** در `/templates` که همان موضوع را به نمونهٔ قابل ویرایش تبدیل کند.

سه خروجی نباید سه موضوع جدا باشند. مقاله، آموزش و قالب باید یکدیگر را تقویت کنند و به یک intent اصلی پاسخ دهند.

## اصول غیرقابل مذاکره

- محتوا برای حل مسئلهٔ کاربر نوشته می‌شود، نه برای پرکردن تقویم.
- هیچ عددی دربارهٔ حجم جست‌وجو، رتبه، CTR یا رقابت بدون دادهٔ واقعی نوشته نمی‌شود.
- تاریخ `updated` فقط پس از بازبینی واقعی متن یا مثال تغییر می‌کند.
- هر کد Mermaid با نسخهٔ فعلی پروژه رندر می‌شود.
- عنوان و توضیح هر صفحه یکتا، فارسی، توصیفی و بدون keyword stuffing است.
- محتوای جدید باید نسبت به نتایج موجود ارزش افزودهٔ روشن داشته باشد: مثال فارسی، تصمیم‌گیری، خطای رایج، چک‌لیست یا تجربهٔ عملی.
- ادعاهای فنی ابتدا با مستندات رسمی Mermaid و سپس با اجرای واقعی در نمودارا بررسی می‌شوند.
- مقالهٔ روزانه نباید موضوعی خارج از تمرکز سایت انتخاب کند، حتی اگر آن موضوع ترند باشد.

## ابزارهای داده و اولویت آن‌ها

### ۱. Google Search Console

دادهٔ Search Console منبع اولویت‌بندی است، نه منبع تولید ادعای بازاریابی. از این سیگنال‌ها استفاده شود:

- Queryهای دارای impression و رتبهٔ ۴ تا ۲۰: گسترش صفحهٔ موجود یا ساخت صفحهٔ مکمل.
- Queryهای دارای impression بالا و CTR ضعیف: بازبینی عنوان، meta description و تطابق intent.
- Queryهایی که چند URL برای آن‌ها دیده می‌شوند: بررسی cannibalization.
- صفحه‌هایی که پس از تغییر افت کرده‌اند: تحلیل قبل از تولید صفحهٔ جدید.
- URLهای تازه: URL Inspection و درخواست crawl فقط پس از اطمینان از canonical، indexability و محتوای کامل.

پیاده‌سازی فعلی پروژه در `src/server/search-console.js` و داشبورد محتوایی قرار دارد. اگر داده در دسترس نبود، مقدار یا فرصت خیالی ساخته نمی‌شود.

### ۲. آنالیتیکس first-party نمودارا

از داده‌های تعامل برای تشخیص کیفیت استفاده شود:

- زمان تعامل پایین با ورودی مناسب: مقدمه یا ساختار احتمالاً با intent هماهنگ نیست.
- بازشدن کم ادیتور: مثال یا CTA عملی ضعیف است.
- استفاده از کپی کد و قالب: نشانهٔ مفیدبودن نمونه‌ها.
- خروج سریع از آموزش: بررسی سطح دشواری، خطای رندر، طول مقدمه و نبود پاسخ مستقیم.

کد مرتبط در `src/server/analytics.js`، `src/server/growth-insights.js` و `src/server/content-operations.js` قرار دارد.

### ۳. ممیزی فنی داخلی

پیش از انتشار، `src/server/seo-audit.js` و تست‌های SEO باید بررسی کنند:

- status code صحیح
- canonical صحیح
- `index,follow`
- عنوان و description یکتا
- sitemap و `lastmod`
- JSON-LD معتبر
- breadcrumb
- نبود overflow و خطای JavaScript
- دسترسی‌پذیری headingها و لینک‌ها

### ۴. SERP و منابع عمومی

برای فهم intent و شکاف محتوا از نتایج فعلی جست‌وجو استفاده شود، اما متن رقبا بازنویسی نشود. بررسی شود:

- کاربر دنبال تعریف است، آموزش است یا ابزار؟
- نتایج برتر چه سؤال‌هایی را پاسخ می‌دهند؟
- کدام نیاز فارسی‌زبان بدون پاسخ مانده است؟
- آیا موضوع صفحهٔ مستقل می‌خواهد یا باید به صفحهٔ موجود اضافه شود؟
- آیا یک مقالهٔ جدید باعث cannibalization می‌شود؟

### ۵. مستندات رسمی

برای syntax، قابلیت‌های نسخه و محدودیت‌ها، مرجع اصلی مستندات Mermaid است. نمونه‌های غیررسمی فقط برای کشف زاویهٔ محتوا استفاده می‌شوند و باید در نسخهٔ فعلی پروژه آزمایش شوند.

## انتخاب موضوع روز

موضوع باید حداقل یکی از این شرایط را داشته باشد:

- دادهٔ Search Console فرصت مشخص نشان می‌دهد.
- یکی از انواع مهم نمودار در مرکز آموزش پوشش ندارد.
- صفحهٔ موجود intent را ناقص پاسخ می‌دهد.
- قالبی در ادیتور وجود دارد ولی آموزش کافی ندارد.
- یک مسئلهٔ واقعی تیم‌های فنی را می‌توان با مثال Mermaid حل کرد.
- تغییر مستندات رسمی Mermaid نیاز به بازبینی محتوا ایجاد کرده است.

### امتیازدهی پیشنهادی

| معیار | امتیاز |
|---|---:|
| تقاضای واقعی در Search Console | ۰ تا ۵ |
| نزدیکی به موضوع اصلی نمودارا | ۰ تا ۵ |
| امکان ساخت مثال قابل ویرایش | ۰ تا ۴ |
| شکاف محتوای فارسی | ۰ تا ۴ |
| ظرفیت لینک داخلی | ۰ تا ۳ |
| خطر cannibalization | ۰ تا منفی ۵ |
| نیاز به ادعای تأییدنشده | ۰ تا منفی ۵ |

موضوعی که امتیاز کافی ندارد فقط برای حفظ «روزانه‌بودن» منتشر نمی‌شود؛ به‌جای آن یک صفحهٔ موجود به‌روزرسانی می‌شود.

## قالب Brief روزانه

هر بستهٔ روزانه در `content/daily/` قرار می‌گیرد. برای محتوای کوتاه می‌توان از یک فایل `YYYY-MM-DD-topic.json` استفاده کرد؛ برای محتوای کامل، ساختار پوشه‌ای زیر ترجیح دارد:

```text
content/daily/YYYY-MM-DD-topic/
  manifest.json
  article.json
  tutorial.json
  template.json
```

مجموع این فایل‌ها باید اطلاعات زیر را داشته باشد:

- تاریخ
- خوشهٔ موضوعی
- query اصلی
- queryهای فرعی
- intent
- منبع رسمی
- مقاله
- آموزش
- قالب
- عنوان لینک داخلی آموزش برای مقاله

### Query اصلی

Query اصلی باید یک عبارت طبیعی باشد، نه فهرست کلمات. نمونه:

- خوب: `آموزش State Diagram در Mermaid`
- بد: `mermaid state diagram state machine آموزش نمودار`

### Search intent

یکی از intentها به‌صورت روشن ثبت شود:

- یادگیری مفهوم
- انجام کار
- مقایسه و انتخاب
- رفع خطا
- یافتن قالب
- استفاده از ابزار

## استاندارد مقالهٔ تحلیلی

مقاله باید یک تصمیم یا برداشت را روشن کند. ساختار پیشنهادی:

1. پاسخ مستقیم در مقدمه
2. تعریف مسئله و مرز موضوع
3. توضیح گزینه‌ها یا مفاهیم
4. مثال واقعی و قابل رندر
5. جدول مقایسه یا معیار تصمیم
6. خطاهای رایج
7. چک‌لیست اجرایی
8. جمع‌بندی تصمیم‌محور
9. لینک به آموزش و قالب مرتبط

حداقل کیفیت داخلی:

- دست‌کم ۷۰۰ واژهٔ مفید، بدون کش‌دادن مصنوعی
- حداقل پنج بخش
- حداقل یک مثال Mermaid در موضوع‌های فنی
- عنوان توصیفی
- description دقیق و غیرتبلیغاتی
- سه takeaway یا بیشتر
- نویسنده و روش بازبینی روشن
- تاریخ انتشار و به‌روزرسانی واقعی

## استاندارد آموزش

آموزش باید کاربر را از یک نمونهٔ سالم به کاربرد عملی برساند:

1. نتیجه‌ای که کاربر خواهد ساخت
2. ساده‌ترین syntax معتبر
3. توضیح هر جزء
4. قابلیت‌های میانی
5. قابلیت‌های پیشرفته فقط در صورت نیاز
6. مثال واقعی
7. خطاهای رایج
8. چک‌لیست بازبینی
9. FAQ

حداقل کیفیت داخلی:

- دست‌کم ۹۰۰ واژهٔ مفید
- حداقل هفت بخش
- حداقل سه پرسش رایج
- چند مثال کوتاه به‌جای یک کد بسیار بزرگ
- مثال کامل نهایی
- متن فارسی با شناسه‌های فنی پایدار
- تمام نمونه‌ها قابل رندر در Mermaid نسخهٔ پروژه

## استاندارد قالب

قالب باید:

- یک مسئلهٔ واقعی را حل کند.
- بدون ویرایش رندر شود.
- عنوان و توضیح مشخص داشته باشد.
- با جست‌وجوی فارسی و انگلیسی پیدا شود.
- نقطهٔ شروع باشد، نه دموی تزئینی.
- اطلاعات حساس، دامنهٔ واقعی مشتری یا credential نداشته باشد.
- با آموزش همان خوشه سازگار باشد.

## On-page SEO

### Title

- یکتا و توصیفی
- query اصلی در صورت طبیعی‌بودن
- بدون تکرار چند شکل از یک کلمه
- برند فقط یک‌بار و توسط سیستم
- هماهنگ با H1 و محتوای واقعی

### Meta description

- خلاصهٔ دقیق کل صفحه
- شامل نتیجه‌ای که کاربر می‌گیرد
- بدون ادعای «بهترین»، «تضمینی» یا رتبه
- نه فهرست کلمات کلیدی
- در حدودی که کامل و خوانا باشد؛ طول ثابت هدف رتبه‌بندی نیست

### Heading

- یک H1
- H2ها سؤال یا بخش واقعی محتوا را بیان کنند
- heading صرفاً برای قرار دادن keyword ساخته نشود
- ترتیب منطقی حفظ شود

### Keyword usage

- query اصلی در title، H1 یا شروع متن فقط وقتی طبیعی است
- مترادف‌ها و اصطلاحات فنی در متن بر اساس نیاز
- هیچ density هدفی وجود ندارد
- عبارت فارسی و اصطلاح انگلیسی در نخستین کاربرد روشن شوند

### Internal linking

هر بستهٔ روزانه باید به این مسیرها متصل شود:

- مقاله → آموزش‌های مرتبط
- آموزش → آموزش قبلی/بعدی، قالب و ادیتور
- قالب → ادیتور
- hubهای `/articles`، `/learn` و `/templates` → محتوای تازه
- صفحات قدیمی مرتبط → صفحهٔ جدید در یک به‌روزرسانی جداگانه، وقتی لینک واقعاً مفید است

Anchor text باید دقیق و طبیعی باشد؛ از «اینجا کلیک کنید» و تکرار افراطی exact-match پرهیز شود.

## Structured data

پروژه به‌صورت خودکار این داده‌ها را تولید می‌کند:

- `Article` برای مقاله‌ها
- `TechArticle` و FAQ برای آموزش‌ها
- `BreadcrumbList`
- `CollectionPage` و `ItemList`
- `WebSite` و `Organization`

پس از انتشار:

1. خروجی JSON-LD از صفحه خوانده شود.
2. با Rich Results Test یا Schema Markup Validator بررسی شود.
3. `datePublished` و `dateModified` با متن صفحه یکسان باشند.
4. author URL معتبر باشد.
5. تصویر معرفی قابل crawl باشد.
6. داده‌ای که در صفحه دیده نمی‌شود وارد schema نشود.

## Technical SEO

هر صفحهٔ جدید باید این شرایط را داشته باشد:

- URL کوتاه، lowercase و پایدار
- پاسخ ۲۰۰
- canonical به خود صفحه
- robots قابل ایندکس
- حضور در sitemap
- `lastmod` واقعی
- زبان `fa-IR` و جهت RTL
- Open Graph و Twitter metadata
- breadcrumb
- لینک از حداقل یک hub
- نبود query parameter در canonical
- نبود trailing-slash duplicate
- سرعت و چیدمان مناسب موبایل
- کد و فونت بدون خطای console
- مثال Mermaid بدون درخواست شبکهٔ خارجی

## فرآیند انتشار خودکار

فایل روزانه به مسیر زیر اضافه می‌شود:

```text
content/daily/YYYY-MM-DD-topic/
  manifest.json
  article.json
  tutorial.json
  template.json
```

Workflow:

```text
content JSON
  → scripts/publish-daily-content.mjs
  → article-content.js
  → learn-content.js
  → templates.js
  → seo.js
  → node --test
  → npm run check
  → render all Mermaid examples
  → commit generated files
```

Workflow در `.github/workflows/publish-daily-content.yml` قرار دارد. انتشار مستقیم محتوای اعتبارسنجی‌نشده ممنوع است.
