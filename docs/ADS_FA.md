# راه‌اندازی درآمد تبلیغاتی ایرانی در Mermaid Studio

Mermaid Studio برای همهٔ کاربران رایگان می‌ماند و درآمد نسخهٔ عمومی فقط از تبلیغات صفحات محتوایی تأمین می‌شود. ادیتور و renderer داخلی عمداً هیچ اسکریپت تبلیغاتی شخص ثالثی ندارند تا شبکهٔ تبلیغاتی به کد، فایل، localStorage یا نمودار کاربر دسترسی پیدا نکند.

## نتیجهٔ تحقیق دربارهٔ شناسه‌های واقعی

`ADS_SCRIPT_URL`، `ADS_SCRIPT_ID` و شناسهٔ placement مقدار عمومی یا مشترک نیستند. این مقادیر بعد از ثبت سایت، بررسی دامنه و ساخت جایگاه در پنل همان حساب ناشر تولید می‌شوند.

بنابراین:

- نمی‌توان شناسهٔ واقعی حساب شما را از وب یا مخزنهای عمومی استخراج کرد.
- شناسهٔ منتشرشده در کد سایت دیگر متعلق به همان ناشر است و نباید استفاده شود.
- استفاده از شناسهٔ ناشر دیگر ممکن است درآمد را به حساب او نسبت دهد، با دامنهٔ شما معتبر نباشد یا باعث نقض سیاست شبکه شود.
- تنها منبع معتبر، snippet نهایی‌ای است که پنل حساب خودتان بعد از تأیید سایت نمایش می‌دهد.

زیرساخت پروژه طوری نوشته شده که snippet معتبر پنل را بدون hard-code کردن اطلاعات حساب در Git وارد کند.

## جایگاه‌های آماده

| متغیر محیطی | محل نمایش |
|---|---|
| `ADS_SLOT_HOME_TOP` | صفحهٔ اصلی، پس از معرفی اولیه |
| `ADS_SLOT_HOME_INLINE` | صفحهٔ اصلی، میان بخش‌های محتوایی |
| `ADS_SLOT_TEMPLATES_TOP` | ابتدای کتابخانهٔ قالب‌ها |
| `ADS_SLOT_TEMPLATES_INLINE` | بعد از فهرست قالب‌ها |
| `ADS_SLOT_LEARN_TOP` | ابتدای مرکز آموزش و مقاله‌ها |
| `ADS_SLOT_LEARN_INLINE` | میان یا انتهای محتوای آموزشی |

هر جایگاه خالی باشد، هیچ placement و درخواست شبکه‌ای برای آن ساخته نمی‌شود.

## یکتانت: الگوی تأییدشدهٔ snippet

در نمونه‌های عمومی سایت‌های ناشر، bootstrap یکتانت معمولاً این ساختار را دارد:

```html
<script
  id="ua-script-PUBLISHER_KEY"
  data-analyticsobject="yektanet"
  src="https://cdn.yektanet.com/rg_woebegone/scripts_v3/PUBLISHER_KEY/rg.complete.js?v=..."
  async>
</script>
```

و جایگاه‌ها معمولاً `div`ای با شناسه‌ای شبیه این هستند:

```html
<div id="pos-article-display-card-123456"></div>
```

`PUBLISHER_KEY` و عدد جایگاه در مثال بالا ساختگی‌اند. قالب کلی برای تشخیص اجزای snippet مفید است، اما هیچ مقدار نمونه‌ای قابل استفاده در production نیست.

### استخراج دقیق از کد پنل یکتانت

پس از ثبت و تأیید سایت:

1. برای هر بخش سایت جایگاه جدا بسازید تا درآمد و RPM قابل تفکیک باشد.
2. کد کامل ارائه‌شده توسط پنل را باز کنید.
3. مقدار `src` تگ script را بدون تغییر در `ADS_SCRIPT_URL` قرار دهید.
4. مقدار `id` همان script را در `ADS_SCRIPT_ID` قرار دهید.
5. مقدار `id` هر div تبلیغ را در متغیر جایگاه متناظر قرار دهید.
6. origin مربوط به `src` و originهای دیگری را که همان snippet واقعاً درخواست می‌کند، دقیقاً در `ADS_ALLOWED_ORIGINS` وارد کنید.

نمونهٔ تنظیم، فقط برای نمایش ساختار:

```dotenv
ADS_ENABLED=true
ADS_PROVIDER=yektanet
ADS_SCRIPT_URL=https://cdn.yektanet.com/rg_woebegone/scripts_v3/PUBLISHER_KEY/rg.complete.js
ADS_SCRIPT_ID=ua-script-PUBLISHER_KEY
ADS_ALLOWED_ORIGINS=https://cdn.yektanet.com,https://*.yektanet.com
ADS_LOAD_DELAY_MS=700

ADS_SLOT_HOME_INLINE=pos-article-display-card-111111
ADS_SLOT_TEMPLATES_INLINE=pos-article-display-card-222222
ADS_SLOT_LEARN_INLINE=pos-article-display-card-333333
```

مقادیر `PUBLISHER_KEY` و اعداد بالا باید با خروجی پنل خودتان جایگزین شوند.

## تپسل: مرز اطلاعات عمومی

صفحهٔ عمومی ناشران تپسل وجود پنل درآمد و آمار را توضیح می‌دهد، اما یک قرارداد عمومی و قابل اتکای ثابت برای تبلیغات وب—شامل CDN، نام تابع initialization و ساختار placement—منتشر نشده است. به همین علت پروژه هیچ URL، تابع یا zone ID حدسی برای تپسل ندارد.

پس از دریافت snippet تپسل:

1. `ADS_PROVIDER=tapsell` را تنظیم کنید.
2. URL دقیق script را در `ADS_SCRIPT_URL` قرار دهید.
3. شناسهٔ script و placementهای واقعی را وارد کنید.
4. اگر snippet علاوه بر script و div یک تابع initialization دارد، قبل از انتشار باید `public/js/ads.js` دقیقاً مطابق همان قرارداد پنل تطبیق و تست شود.
5. originهای واقعی مشاهده‌شده در DevTools را به CSP اضافه کنید؛ نه wildcard عمومی `*` و نه `https:`.

تا زمانی که snippet واقعی پنل دریافت نشده، تپسل را فعال نکنید.

## روند امن راه‌اندازی

1. سایت را با `ADS_ENABLED=false` روی دامنهٔ نهایی منتشر کنید.
2. دامنه را در پنل ناشر ثبت و تأیید کنید.
3. ابتدا سه جایگاه میان‌صفحه بسازید:

```dotenv
ADS_SLOT_HOME_INLINE=...
ADS_SLOT_TEMPLATES_INLINE=...
ADS_SLOT_LEARN_INLINE=...
```

4. snippet را در `.env` وارد کنید و سرویس app را restart کنید.
5. در DevTools شبکه و Console را بررسی کنید.
6. اطمینان بگیرید `/editor` و `/headless` هیچ درخواست تبلیغاتی ندارند.
7. impression، click و درآمد گزارش پنل را در داشبورد `/admin/analytics` ثبت کنید.
8. Page RPM، eCPM، CTR، سرعت و نرخ ورود به ادیتور را حداقل یک تا دو هفته مقایسه کنید.
9. فقط در صورت حفظ تجربهٔ کاربر، جایگاه‌های بالای صفحه را آزمایش کنید.

## Content Security Policy

هنگام فعال‌شدن تبلیغات، فقط originهایی که پنل واقعاً استفاده می‌کند در `ADS_ALLOWED_ORIGINS` قرار دهید. چند origin را با ویرگول جدا کنید و فقط HTTPS وارد کنید.

اگر منبعی با CSP مسدود شد:

- URL خطا را بررسی کنید.
- مطمئن شوید متعلق به snippet رسمی پنل است.
- فقط origin همان منبع را اضافه کنید.
- هرگز برای رفع سریع خطا از `*`، `https:` یا `unsafe-eval` استفاده نکنید.

## اصول سیاست و تجربهٔ کاربر

- جایگاه با عبارت «تبلیغات» مشخص است.
- تبلیغ پاپ‌آپ، تمام‌صفحه و تبلیغ روی دکمهٔ دانلود استفاده نمی‌شود.
- از کاربر درخواست کلیک نکنید و خودتان روی تبلیغ زنده کلیک نکنید.
- ترافیک، impression یا click مصنوعی نسازید.
- تبلیغ را کنار دکمه‌های دانلود، کپی و ورود به ادیتور قرار ندهید.
- تعداد placement را بر اساس RPM و retention انتخاب کنید، نه صرفاً تعداد بنر.
- کد Mermaid، محتوای ادیتور و URL hash را به شبکه ارسال نکنید.

## خاموش‌کردن فوری

```dotenv
ADS_ENABLED=false
```

پس از restart، `/api/ads` حالت غیرفعال برمی‌گرداند و مرورگر هیچ script شخص ثالثی بارگذاری نمی‌کند.
