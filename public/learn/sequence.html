نمودار توالی در Mermaid

Sequence Diagram ترتیب پیام‌ها میان بازیگران و سرویس‌ها را نشان می‌دهد. برای مستندسازی API، فرایند ورود، پرداخت و ارتباط میکروسرویس‌ها بسیار کاربردی است.

زمان مطالعه: ۹ دقیقهسطح: مقدماتیمناسب مستندات API

ساخت اولین نمودار توالی

نمودار با sequenceDiagram شروع می‌شود. شرکت‌کنندگان را با participant معرفی کن و سپس پیام‌ها را به ترتیب بنویس.

ورود کاربرویرایش در ادیتور
sequenceDiagram
    participant U as کاربر
    participant W as وب‌اپ
    participant A as API
    U->>W: ارسال فرم ورود
    W->>A: POST /login
    A-->>W: access token
    W-->>U: نمایش داشبورد

انواع پیکان

  • ->>: پیام با پیکان پر
  • -->>: پاسخ خط‌چین
  • -): پیام غیرهم‌زمان
  • -x: پیام خاتمه‌یافته یا ناموفق

برای خوانایی، معمولاً درخواست را با خط کامل و پاسخ را با خط‌چین نمایش می‌دهند.

نمایش زمان پردازش

با علامت‌های + و - می‌توان فعال‌شدن و پایان پردازش یک سرویس را نمایش داد.

فعال‌سازی سرویسویرایش در ادیتور
sequenceDiagram
    participant A as API
    participant D as Database
    A->>+D: SELECT user
    D-->>-A: user row

شرط و مسیر جایگزین

بلوک alt برای شرط، else برای مسیر جایگزین و end برای پایان بلوک استفاده می‌شود.

پرداخت موفق یا ناموفقویرایش در ادیتور
sequenceDiagram
    participant U as کاربر
    participant P as درگاه پرداخت
    U->>P: پرداخت سفارش
    alt پرداخت موفق
      P-->>U: کد رهگیری
    else پرداخت ناموفق
      P-->>U: پیام خطا
    end

تکرار و اجرای موازی

از loop برای تکرار و از par برای کارهای موازی استفاده کن.

تلاش دوبارهویرایش در ادیتور
sequenceDiagram
    participant C as Client
    participant A as API
    loop حداکثر سه بار
      C->>A: دریافت وضعیت
      A-->>C: پاسخ
    end

نکات خوانایی

  1. نام فنی شرکت‌کننده را کوتاه و عنوان نمایشی را فارسی انتخاب کن.
  2. درخواست و پاسخ را با دو نوع خط متفاوت نشان بده.
  3. برای نمودارهای بلند از autonumber استفاده کن.
  4. جزئیات کم‌اهمیت را در Note بنویس تا مسیر اصلی شلوغ نشود.
مثال: با نوشتن Note over A,D: تراکنش دیتابیس یک توضیح روی چند شرکت‌کننده قرار می‌گیرد.
